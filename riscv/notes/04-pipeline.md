# 阶段四：流水线基础

> 注意：本项目的 RTL 实现为**单周期处理器**，流水线设计是进阶内容。本章帮助你理解流水线的基本概念，为后续升级到流水线处理器铺垫理论基础。

## 1. 流水线的核心思想

### 类比：洗衣房

**非流水线**（单周期）：
```
时间 →  [装] [洗] [烘] [叠]  →  完成衣服1
        ............[装] [洗] [烘] [叠]  →  完成衣服2
```
每人独占所有资源，上一个人全部完成下一个人才能开始。

**流水线**：
```
时间 →  [装] [洗] [烘] [叠]
        [装] [洗] [烘] [叠]
        [装] [洗] [烘] [叠]
        [装] [洗] [烘] [叠]
```
每人完成后交给下一阶段，自己立即开始处理下一件。

- 非流水线：完成4件需 16 个阶段时间（4件 × 4阶段/件）
- 流水线：完成4件需 7 个阶段时间（4 + 3 = 7，填满+排空）

流水线**不减少每件任务的时间**，但**增加吞吐率**（任务/时间）。

## 2. 经典五级流水线

```
时钟周期:  1     2     3     4     5     6     7     8     9
指令1:    [IF]  [ID]  [EX]  [MEM]  [WB]
指令2:          [IF]  [ID]  [EX]  [MEM]  [WB]
指令3:                [IF]  [ID]  [EX]  [MEM]  [WB]
指令4:                      [IF]  [ID]  [EX]  [MEM]  [WB]
指令5:                            [IF]  [ID]  [EX]  [MEM]  [WB]
```

每个时钟周期，所有流水级同时工作在不同的指令上。理想情况下，每个周期完成一条指令（CPI ≈ 1）。

### 五级流水寄存器

流水线各级之间插入**流水线寄存器**来分隔：

```
IF/ID寄存器  ID/EX寄存器  EX/MEM寄存器  MEM/WB寄存器
   | |          | |          | |          | |
 [IF] -------> [ID] -------> [EX] -------> [MEM] -------> [WB]
```

这些寄存器保存了每一级的所有输出信号（指令、控制信号、数据），传递给下一级。它们由同一个时钟驱动。

## 3. 流水线的三大冒险 (Hazards)

流水线之所以难设计，是因为指令之间存在依赖关系。

### 3.1 结构冒险 (Structural Hazard)

**问题**：两条指令同时需要同一硬件资源。

**例子**：单端口存储器，IF 阶段取指令 + MEM 阶段读数据 → 冲突！

```
指令1: [IF] [ID] [EX] [MEM] [WB]
指令4:                [IF] ...  ← 与指令1的MEM冲突！都需要访问存储器
```

**解决方案**：
- 哈佛架构（分离 I-mem 和 D-mem）
- 指令缓存 + 数据缓存分离（现代处理器）
- 插入气泡（暂停）—— 但会降低性能

### 3.2 数据冒险 (Data Hazard)

**问题**：后一条指令依赖前一条指令尚未写回的结果。

**例子**：
```asm
add  x1, x2, x3    # x1 = x2 + x3
sub  x4, x1, x5    # x4 = x1 - x5  ← 依赖 x1，但 add 还没写回！
```

在流水线中：
```
add:  [IF] [ID] [EX] [MEM] [WB]    ← x1 在 WB 结束时才写入 regfile
sub:        [IF] [ID] ...           ← ID 阶段需要读 x1，但 add 才到 EX！
```

sub 在 ID 阶段需要 x1 的值，但 add 的 x1 值要到 WB 阶段才写回寄存器文件——差了3个周期！

**解决方案**：

#### a) 转发 (Forwarding / Bypassing)
不需要等到写回！一旦 EX 阶段算出结果，就通过旁路路径直接送到下一条指令需要的地方。

```
add:  [IF] [ID] [EX] ->\
                          \--- x1 的值（从 EX/MEM 管道寄存器直接转发）
sub:        [IF] [ID] ->/      不需要等到 WB！
```

转发路径：
- **EX/MEM → ID 阶段**（隔 1 条指令）
- **MEM/WB → ID 阶段**（隔 2 条指令）

#### b) 停顿 (Stall / Pipeline Bubble)
有些冒险即使转发也解决不了——比如 load-use 冒险：

```asm
lw   x1, 0(x2)      # x1 = mem[x2+0]  ← 数据要在 MEM 阶段才得到
add  x3, x1, x4     # x3 = x1 + x4    ← ID 阶段就需要 x1！
```

lw 的数据在 MEM 阶段才能获得，而 add 在 EX 阶段就需要——即使用了转发，还是差一个周期。

**解决**：插入一个**气泡**（暂停 add 一个周期，让 lw 把数据转发过来）：

```
lw:  [IF] [ID] [EX] [MEM] [WB]
add:       [IF] [ID] [stall] [EX] [MEM] [WB]
                        ↑ 插入一个空操作周期
```

这本质上把 CPI 提高了一点（牺牲性能换正确性）。

### 3.3 控制冒险 (Control Hazard)

**问题**：分支指令在 EX 阶段才知道是否跳转，但后续指令已经在 IF/ID 阶段了。

```asm
beq  x1, x2, target  # 如果相等则跳转
add  x3, x4, x5      # 如果跳转，这条不该执行！
sub  x6, x7, x8      # 如果跳转，这条也不该执行！
```

在流水线中：
```
beq:  [IF] [ID] [EX] ← 在这里才知道是否跳转
add:        [IF] [ID] ← 这两条已经进入流水线！
sub:              [IF] ←
```

**解决方案**（从简单到复杂）：

#### a) 停顿直到分支结果确定
在分支结果确定前，不取新指令 → CPI 损失很大（每个分支等 2 个周期）。

#### b) 分支预测 (Branch Prediction)
- **始终不跳转 (Predict Not Taken)**：总是继续顺序取指令。如果猜对了：无损失；猜错了：flush 流水线，重新取。
- **始终跳转 (Predict Taken)**：总是取目标地址的指令。
- **动态预测**：根据历史行为预测（2-bit 饱和计数器、BTB 等）。

#### c) 延迟分支 (Delayed Branch)
编译器在分支指令后填充一条无论如何都会执行的指令：
```asm
beq  x1, x2, target
add  x3, x4, x5      # ← 这条总是执行！（在延迟槽中）
```
现代高性能处理器很少使用此技术（超标量让这变得更复杂）。

## 4. 从单周期到流水线：需要改什么？

### 硬件变化
1. **插入流水线寄存器**（IF/ID、ID/EX、EX/MEM、MEM/WB）
2. **添加转发多路复用器**（从 EX/MEM 和 MEM/WB 转发回 EX 阶段输入）
3. **添加冒险检测单元**（检测 load-use 冒险 → 插入停顿）
4. **添加 flush 逻辑**（分支预测错误时清空流水线）

### 控制信号的流水线传递
控制信号也需要沿流水线传递：
```
Control Unit 产生信号 →
  IF/ID: (无控制信号)
  ID/EX: RegWrite, ALUSrc, MemWrite, MemRead, MemtoReg, ALUOp...
  EX/MEM: RegWrite, MemWrite, MemRead, MemtoReg...
  MEM/WB: RegWrite, MemtoReg...
```

## 6. 进阶话题预告

学完单周期处理器和流水线基础后，可以进一步探索：

- **超标量 (Superscalar)**：每个周期发射多条指令
- **乱序执行 (Out-of-Order)**：指令不按程序顺序执行，但按顺序提交
- **分支预测器**：BTB、G-share、TAGE
- **缓存 (Cache)**：I-cache、D-cache、多级缓存层次
- **虚拟内存与 TLB**
- **多核与缓存一致性**
