# 阶段三：CPU 微架构

## 1. 架构 vs 微架构

| | 架构 (Architecture) | 微架构 (Microarchitecture) |
|---|-------------------|-------------------------|
| 定义 | 软件的接口 | 硬件的实现 |
| 可见性 | 对程序员可见 | 对程序员透明 |
| 例子 | RISC-V RV32I（必须实现 ADD 等指令） | 单周期 / 多周期 / 流水线 / 超标量 |
| 谁关心？ | 编译器作者、汇编程序员 | 芯片设计师 |

同一个 RISC-V ISA 可以有不同的微架构实现——这就像同一个 API 可以有不同的后端实现。

## 2. 冯·诺依曼架构 vs 哈佛架构

### 冯·诺依曼架构
```
┌──────┐    总线    ┌──────────┐
│ CPU  │ <=======> │ 统一存储器 │  （指令+数据共享一条总线）
└──────┘           └──────────┘
```
- 优点：硬件简单，存储器利用率高
- 缺点：无法同时取指令和存取数据（**冯·诺依曼瓶颈**）
- 对应：本项目的 `memory.v` 统一指令/数据存储器

### 哈佛架构
```
┌──────┐    指令总线  ┌──────────┐
│ CPU  │ ==========> │ 指令存储器 │
│      │ <=========> │ 数据存储器 │
└──────┘    数据总线  └──────────┘
```
- 优点：指令和数据可同时访问（适合流水线）
- 缺点：需要两套总线，硬件成本高
- 对应：L1 I-cache + L1 D-cache 的现代处理器

我们的单周期处理器教学模型采用冯·诺依曼架构简化设计，但为每个模块定义了清晰的总线接口。

## 3. 处理器的经典五阶段

无论什么微架构，处理器的数据通路都可以按功能分为五个阶段：

```
┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐   ┌──────────┐
│ IF       │   │ ID       │   │ EX       │   │ MEM      │   │ WB       │
│ 取指令   │──>│ 指令译码 │──>│ 执行运算 │──>│ 存储器访问│──>│ 写回     │
│          │   │ 读寄存器 │   │          │   │          │   │          │
└──────────┘   └──────────┘   └──────────┘   └──────────┘   └──────────┘
```

### IF (Instruction Fetch) — 取指令
- **输入**：PC (Program Counter)
- **操作**：`instruction = mem[PC]`
- **输出**：当前指令的 32-bit 机器码
- **关键模块**：`pc.v`, `memory.v`

### ID (Instruction Decode) — 指令译码
- **输入**：32-bit 指令
- **操作**：
  1. 从指令中提取各字段（opcode, rd, rs1, rs2, funct3, funct7, imm）
  2. 根据 opcode 生成控制信号
  3. 从寄存器文件读取 rs1, rs2 的值
- **输出**：控制信号 + 寄存器数据
- **关键模块**：`control_unit.v`, `regfile.v`, `imm_gen.v`

### EX (Execute) — 执行
- **输入**：寄存器数据 + 控制信号 + 立即数
- **操作**：
  1. ALU 运算（加减、逻辑、移位、比较）
  2. 地址计算（load/store 的有效地址 = rs1 + offset）
  3. 分支条件判断（beq: rs1==rs2?）
- **输出**：ALU 结果 / 分支是否跳转
- **关键模块**：`alu.v`

### MEM (Memory Access) — 存储器访问
- **输入**：地址 + 写数据 + MemRead/MemWrite 信号
- **操作**：Load（读内存）/ Store（写内存）
- **输出**：读出的内存数据（load）或无（store）
- **关键模块**：`memory.v`

### WB (Write Back) — 写回
- **输入**：MemtoReg 选择信号 + ALU 结果 + 内存数据
- **操作**：选择将 ALU 结果还是内存数据写回寄存器文件
- **输出**：写回寄存器的值
- **关键模块**：`regfile.v`

## 4. 单周期处理器的数据通路

在单周期设计中，**所有五个阶段在同一时钟周期内完成**。这是最简单的微架构，适合理解基本原理。

### 完整数据通路图

```
                          +-----+
                          | PC  |<--------+
                          +--+--+         |
                             |            |
                             v            |
                         +---+---+        |
          imm_gen <------+ instr +------->+
                         +---+---+        |
                             |            |
                    control_unit         |
                         |    |           |
                         v    v           |
                    +----+----+----+      |
       rs1 -------->|         |    |      |
                    | regfile |    |      |
       rs2 -------->|         |    |      |
                    +----+----+----+      |
                         |    |           |
                         v    v           |
                    +----+----+----+      |
                    |   rs1  rs2  |       |
                    |    \   /    |       |
                    |     ALU     |       |
                    |      |      |       |
                    +------+------+       |
                           |              |
                           v              |
                      +----+----+         |
                      | memory  |         |
                      +----+----+         |
                           |              |
                   (MemtoReg mux)         |
                           |              |
                           v              |
                      +---------+         |
        write_data--->| regfile |---------+ (next PC)
                      +---------+
```

### PC 更新逻辑

PC 的下一值取决于当前指令类型：

```
if (branch_taken)
    next_pc = pc + branch_offset    // 分支预测命中
else if (jal)
    next_pc = pc + jal_offset       // 无条件跳转
else if (jalr)
    next_pc = rs1 + jalr_offset     // 间接跳转
else
    next_pc = pc + 4                // 顺序执行
```

### 控制信号生成逻辑

```
opcode ──────────────────────────────────────
  |       |       |      |      |      |   |
  v       v       v      v      v      v   v
R-type  I-type  Load  Store  Branch  JAL  JALR
  |       |       |      |      |      |   |
  +--> RegWrite=1   RegWrite=1  RegWrite=0  ...
  |     ALUSrc=0     ALUSrc=1    MemWrite=1
  |     MemtoReg=0   MemtoReg=1  Branch=0
  |     ALUOp=10     ALUOp=00    ALUOp=00
  ...    ...        ...         ...
```

## 5. 单周期设计的性能问题

### 关键路径 (Critical Path)

单周期处理器中最长的组合路径决定了时钟频率：

```
PC → 指令存储器 → 译码 → 寄存器读取 → ALU → 数据存储器 → MUX → 寄存器写
```

这个路径包含了存储器和ALU的延迟之和。LUI 指令不需要 ALU，可能很快；LW 指令需要走完整条路径，是最慢的。

### 分析
- **优点**：设计简单，每条指令恰好一个周期
- **缺点**：
  - 时钟周期由最慢指令决定（LW），其他指令也受此限制
  - 所有硬件在一个周期内只被使用一次——利用率极低
  - 不适合实际产品

### 为什么不直接用单周期？
设 `T_mem = 200ps, T_ALU = 100ps, T_reg = 50ps, T_mux = 20ps`

一条 LW 指令延迟 ≈ 200 + 50 + 20 + 100 + 200 + 20 + 50 = 640ps

一条 ADD 指令延迟 ≈ 200 + 50 + 20 + 100 + 20 + 50 = 440ps

但在单周期设计中，**所有指令都必须以 640ps 为周期**。ADD 浪费了 200ps。

## 6. 性能公式

```
执行时间 = 指令数 × CPI × 时钟周期
```

| 参数 | 单周期 | 流水线 |
|------|--------|--------|
| CPI | 1 | ~1 (理想) |
| 时钟周期 | 由最慢指令决定 | 由最慢流水级决定 |
| 总体 | 基准 | 更快（更短时钟周期） |

理解了这个权衡，就知道为什么要引入流水线了。进入 [阶段四：流水线](04-pipeline.md) 了解更多。
