# 信号设计与命名指南

> 本文档定义逻辑设计中的信号设计理论和命名规范。

---

## 第一部分：命名规范

### 1.1 核心原则

【原则】**简单、名副其实、全项目一致**

【原则】**名词（主体）做后缀，修饰词（形容词/副词/动词）做前缀**（dly除外）

### 1.2 命名结构

```text
信号名 = [修饰前缀] + [功能描述] + [本质属性后缀]
          ↑              ↑                   ↑
    形容词/副词/动词   动词/名词           名词（核心）
```

【示例】
- 主体名词：_cnt（计数器）、_dat（数据）、_id（索引）、_flag（标志）、_vld（有效）、_en（使能）、_sof（帧起始）
- 修饰词：ram_（RAM的）、mult_（乘法器的）、src_（源）、task_（任务的）
- 其他修饰词：good_（好的）、cur_（当前）、nxt_（下一个）、wr_（写）

【示例】任务结束信号索引应命名为 `task_eof_id`，**不是** `task_id_eof`

【原则】每个信号的层次必须固定，generate块必须命名

【规则】每个for循环加块名，每个generate if加块名

【规则】除公共模块外，**子模块名应为"父模块_缩写"**，且**缩写不含"_"**

【规则】除公共模块外，**例化名应为"u_缩写"**，多个例化时加后缀不加"_"

【指导】Generate名应简短，避免层次过长

## 第二部分：信号设计理论

### 2.1 信号含义完整性

【核心公式】**信号含义 = 属性 + 时刻 + 行为**

#### 三个维度

| 维度 | 描述 | 示例 |
|------|------|------|
| **属性** | 信号的值或状态 | cnt值、fifo个数 |
| **时刻** | 当前/上一/下一时刻 | 当前时刻之前、上一时刻之前 |
| **行为** | 行为信号的发生 | en/vld是否发生（可能为0、可能为1） |

#### 正确理解示例

**示例1**：`(fifo_rd_avcnt==5)`
- **含义**：当前时刻（时刻），有5个数据可读（属性）
- **注意**：**不包含行为**，仅表示状态

**示例2**：`fifo_rd_avcnt + (wr_en ? 1'b1 : 1'b0)`
- **含义**：当前时刻（时刻），在wr_en行为发生后（行为，wr_en可能为0、可能为1），可读数据个数
- **注意**："行为"一般只在普通信号与行为信号进行与或非运算时使用

**示例3**：`(cnt == M)`
- **正确**：当前时刻之前（时刻），来过M个en（属性）
- **错误**：假设en连续，表示第M+1个en（引入了假设条件）

**示例4**：`(nxt_cnt == M)`（nxt_cnt是cnt寄存器的D端）
- **含义**：下个时刻之前/当前时刻结束（时刻），来过M个en（属性）

### 2.2 信号类型

#### 按语义属性

| 类型 | 语义 | 示例 | 产生方式 |
|------|------|------|---------|
| **行为信号** | 触发动作 | rd_en/wr_en/calc_en/sof/eof | 条件组合 |
| **状态信号** | 描述区间 | working/f_working/l_working | 起止信号锁存 |
| **参数信号** | 配置信息 | pd/mode/param/dat | 启动时刻配置 |
| **条件信号** | 判断依据 | match/valid/ready/full | 逻辑比较 |

#### 行为信号

仅在条件满足时触发，通常由多个条件组合而成。

【示例】
```verilog
assign rd_en = pre_ready && post_ready && state_ready;
```

**原则**：行为信号驱动整个设计状态演进。

#### 状态信号

常见区间信号产生方法：

1. `sof/eof/f_working` → 串行任务
2. `working && (cnt == A)` → 循环任务
3. `working && (mode == type_a)` → MUX任务
4. `working && (!sub1_working) || sub2_working` → 串行任务

#### 按能量属性

| 类型 | 描述 | 范围 |
|------|------|------|
| **有能量信号** | 驱动设计的关键控制信号 | 启动(so?)、结束(eo?)、工作状态(?working)、使能(en/vld)、状态(cs/ns) |
| **无能量信号** | 数据、参数、状态标志 | dat、pd、mode、cnt等 |

【原则】**最小能量原则：仅用最少的有能量信号把控设计进程！**

【规则】只有核心控制通路上的行为信号和区间信号可以是有能量信号。

### 2.3 "名副其实"原则

#### 核心原则

【核心原则】**对齐原则：信号使用时刻与希望使用时刻的时刻差必须补齐**

#### 有效区间 vs 使用区间

| 概念 | 定义 | 关系 |
|------|------|------|
| **有效区间** | 信号可以使用的时刻区间 | 名副其实的区间 |
| **使用区间** | 信号需要使用的时刻区间 | 设计需求的区间 |

【规则】**信号有效区间 <= 信号名副其实区间**

【规则】**信号有效区间 >= 信号使用区间**

#### 有效区间类型

1. **当前时刻有效**：如din、rd_en
2. **一段区间内有效**：如f_working期间的pd、cnt在计数期间
3. **任意时刻有效**：如fifo_rd_avcnt、配置参数

#### 使用区间类型

1. **更新的时刻使用**：如pix_cnt相对vld延迟0拍
2. **更新后使用**：如line_cnt相对vld延迟1拍
3. **某事件发生的时刻使用**：如ready的典型使用场景（事件发生的时刻可能存在随机性，是一个区间）

#### 有效区间扩展

【方法】有效区间一般是名副其实的区间，只要将无效区间信号的值修改为名副其实时需要的值，就可以完成有效区间的扩展。

【示例】
```verilog
// 原设计：rd_num仅在fwk时可用，因此rd_ready仅在fwk时可用
assign rd_ready = (rd_avcnt >= rd_num);  // 仅在fwk时可用

// 扩展后：任意时刻可用
assign rd_en = rd_ready && f_working;    // 任意时刻可用
```

#### 信号含义的转换与推导

【原则】**同一个信号在不同时刻的含义不同，可据此完成信号含义的转换和推导。**

**时序预测公式**：
```text
时刻差 = 寄存器级数 + 时间维扩展和收缩函数
```

**示例推导**：
```text
当前时刻是第N次工作
= 之前已完成N-1次工作 且 当前时刻正在工作

之前已完成N-1次工作（N≥2时）：
= 第N-2次工作完成后 且 第N-1次工作已完成前
```

### 2.4 残余问题

#### 问题定义

寄存器残余是常见的电路设计问题，验证时不易发现，但一旦在实际使用中触发，往往导致系统级异常。

#### 残余规则

| 信号类型 | 残余要求 |
|---------|---------|
| 行为信号 | 必须停止翻转 |
| 区间信号 | 必须返回IDLE |
| eof后使用的信号 | 可保持 |
| eof后不使用的信号 | 建议在eof时复位 |
| 下次sof重新配置的信号 | 可为面积优化保持 |
| 其他 | 必须在eof时复位，**不能**仅在sof时复位 |

【原则】**有能量信号必须关注残余问题。**

## 第五部分：设计能力提升

### 如何提升设计组织性和规范性？

1. 关注**行为信号**和**有能量信号**
2. 理解并落实**信号能量属性规则**

### 如何判断现有设计的正确性？

1. 信号的**实际使用时刻**是否在**允许使用时刻区间**内？
2. **等式两边**在**有效时刻**是否**等价**？

### 如何解决复杂设计问题？

1. **信号含义转换和推导**
2. 判断推导结论的正确性并迭代
