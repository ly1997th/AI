## 第一部分：设计抽象层次（L1）

### 1.1 四层抽象模型

| 层次 | 抽象对象 | 设计活动 | 关键概念 | AI 辅助重点 |
|------|---------|---------|---------|-----------|
| **ESL** | 事务/功能 | 系统建模、架构探索 | TLM、事务、功能模型 | 算法重构、架构选型 |
| **RTL** | 寄存器传输 | 逻辑设计 | 时序、数据流、控制流 | **核心战场**：代码生成、评审 |
| **门级** | 逻辑门 | 综合优化 | 与或非、标准单元 | PPA 评估 |
| **管级** | 晶体管 | 物理实现 | 版图、走线、时序收敛 | 物理约束 |

**前端设计范围**：本文档集覆盖 RTL 层及前端与门级的交互——包括 RTL 编码、功能验证、综合约束（SDC）、门控时钟推断、形式等价性检查。物理布局、时钟树综合、布线等后端活动不在范围之内。

**AI 设计聚焦点**：RTL 层是 AI 辅助设计的核心战场，需建立**时序思维**（寄存器 D 端 / Q 端关系）和**硬件思维**（电路可实现性）。

### 1.2 三域描述法（Y-Chart）

任何设计需从三个维度描述：

- **行为域**：做什么（功能、算法、数据流图）
- **结构域**：怎么做（模块划分、互联关系、并行度）
- **物理域**：用什么做（存储尺寸、端口数量、翻转率、功耗预算）

## 第二部分：控制逻辑实现方法（L1-L2）

### 2.1 状态机方法的问题

**【原则】控制逻辑优先使用任务分解 CBB，而非手工编写状态机**

状态机存在以下根本性问题：

| 问题类别 | 具体表现 | 后果 |
|---------|---------|------|
| **时序不精准** | 基于状态电平，不是基于事件脉冲 | 缺乏具体时刻概念，容易出现时序不对齐缺陷 |
| **流水线难表达** | 打 N 拍需要 N 个新状态 | 代码膨胀，难以维护 |
| **零长度时间片** | 无法表达长度为零的时间片 | 功能受限 |
| **代码电路不对应** | 行为级抽象，代码与电路不对应 | 编码人员失去对实现电路的把控 |
| **易打补丁** | 扩展性高但代码质量普遍变低 | 任务层次耦合，不够结构化 |

### 2.2 推荐方法：基于任务分解的 CBB 方法

**【原则】对于任务分解，采用基于脉冲的、代码和电路对应的行为级抽象、易于扩展且保证质量的新方法——基于任务分解 CBB 的方法**

#### 2.2.1 任务分解的 4 种基本结构

比算法结构化编程范式多一种**并行**结构：

```text
1. 顺序结构（Serial）   → hik_taskdec_serial
2. 分支结构（Demux）      → hik_taskdec_demux_index / hik_taskdec_demux_onehot / hik_taskdec_open
3. 循环结构（Loop）     → hik_taskdec_loop_for / hik_taskdec_loop_while
4. 并行结构（Parallel） → hik_taskdec_paral
```

考虑到资源复用，比算法结构化编程范式再多一种**融合**结构：

```text
5. 融合结构（mix）   → hik_taskdec_mix
```

#### 2.2.2 状态机的正确使用场景

状态机有价值的是它的**思想**：把电路分成三部分——输入组合逻辑、寄存器、扇出电路。

**【原则】该思想在用于时序预测时有奇效，但建议先有电路后有代码！**

**【应用指南】**：
- **优先**：任务分解 CBB → 适用大多数控制流场景
- **例外**：随机握手任务（如仲裁器、中断处理）→ IDLE/WAIT/WORK 三状态 FSM
- **避免**：自定义多状态 FSM → 代码可维护性差，验证覆盖复杂

> 详细的 FSM 编码指南（三状态例外及更多状态时的推荐写法）参见 [08.综合优化指南](../guide_ext/08-综合优化指南.md) 第二部分。

## 第三部分：设计对象分类体系（L1-L2）

### 3.1 按复杂度分层

```text
系统(System) → 模块(Module) → 组件(Component)
```

| 层级 | 定义 | 设计特征 | 判断标准 |
|------|------|---------|---------|
| **系统** | 涌现新功能的整体 | 多模块协同、有全局目标 | 1+1>2 |
| **模块** | 独立完成功能的单元 | 有明确接口、可独立验证 | 单一职责 |
| **组件** | 配合完成功能的逻辑 | 无独立功能、需组合使用 | 可复用性 |

### 3.2 按功能类型分类（冯诺依曼架构）

| 类型 | 核心问题 | 典型组件 | 关键指标 |
|------|---------|---------|---------|
| **控制** | 何时做 | 任务分解 CBB、调度器、仲裁器 | 灵活性、确定性 |
| **计算** | 怎么做 | ALU、乘法器、卷积核 | 精度、吞吐率 |
| **存储** | 存什么 | RAM、FIFO、寄存器堆 | 容量、带宽、功耗 |
| **传输** | 传什么 | 总线、路由、DMA | 带宽、延迟 |

## 第四部分：信号命名规范（L2）

### 4.1 命名结构

```text
信号名 = [修饰前缀] + [功能描述] + [本质属性后缀]
          ↑              ↑              ↑
        形容词/副词    动词/名词      名词（核心）
```

【规则】主体名词做后缀，修饰词做前缀。

【示例】`task_eof_id` 是正确的，`task_id_eof` 是错误的。

### 4.2 常用后缀

#### 控制类

| 后缀 | 含义 | 方向 | 示例 |
|------|------|------|------|
| _so? | 启动脉冲 | M→S | sof, sol |
| _eo? | 结束脉冲 | S→M | eof, eol |
| _?working | 工作状态 | S→M | f_working |
| _en | 使能（电平） | M→S | wr_en |
| _vld | 有效（脉冲） | M→S | dat_vld |
| _valid | 前有数状态 | M→S | data_valid |
| _ready | 后有空状态 | S→M | data_ready |

#### 数据类

| 后缀 | 含义 | 示例 |
|------|------|------|
| _dat | 数据 | wr_dat, rd_dat |
| _pd | 打包参数 | task_pd |
| _addr | 地址 | wr_addr |
| _cnt | 计数器 | col_cnt |
| _num | 数量 | task_num |

#### 时序类

| 后缀 | 含义 | 示例 |
|------|------|------|
| _d? | 延时 | sig_d1, sig_d2 |
| _fst | 第一个 | en_fst |
| _lst | 最后一个 | en_lst |

### 4.3 命名词典精选

| 类别 | 示例 |
|------|------|
| 操作 | add, sub, mult, div, acc, sum, floor, ceil, round, fpga_round |
| 存储 | mem, ram, buf, fifo, ddr |
| 序列 | head, tail, pre, post, nxt, lst, dly |

## 第五部分：信号设计理论（L1-L3）

### 5.1 信号含义完整性

【核心公式】**信号含义 = 属性 + 时刻 + 行为**

【示例】`(fifo_rd_avcnt==5)` 含义：当前时刻（时刻），有 5 个数据可读（属性）。**不包含行为。**

【示例】`fifo_rd_avcnt + (wr_en ? 1'b1 : 1'b0)` 含义：当前时刻（时刻），在 wr_en 行为发生后（行为，wr_en 可能为 0、可能为 1），可读数据个数。

### 5.2 信号类型

| 类型 | 描述 | 示例 |
|------|------|------|
| 行为信号 | 触发动作 | rd_en, wr_en, sof, eof |
| 状态信号 | 描述区间 | working, f_working |
| 参数信号 | 配置信息 | pd, mode, param |
| 条件信号 | 判断依据 | match, valid, ready |

### 5.3 有能量信号

【原则】**最小能量原则：尽可能少用有能量信号。**

有能量信号：so?, eo?, ?working, en/vld, cs/ns

### 5.4 有效区间 vs 使用区间

【规则】有效区间 <= 名副其实区间

【规则】有效区间 >= 使用区间

## 第六部分：编码规范（L2）

### 6.1 关键语法规则

| 规则 | 描述 |
|------|------|
| 时序逻辑用 '<=' | 组合逻辑用 '=' |
| 每个 if/else 必须有 begin/end | **else 分支必须显式写出** |
| 一行一个声明/表达式 | - |
| 用括号明确优先级 | - |

### 6.2 缩进规则

【规则】**2 空格缩进（不是 4）**

【规则】**begin 另起一行，与 end 对齐**

```verilog
// 正确
always @(posedge clk or negedge rst_n)
begin
  if (!rst_n)
  begin
    sig <= 1'b0;
  end
  else
  begin
    sig <= 1'b1;
  end
end
```

### 6.3 注释规则

【规则】**注释用英文**

【规则】**注释简短** - 每段代码一句话

【规则】只用 '//'，**不用 '/**/'**

### 6.4 代码段落结构

每个段落包含（全部可选）：
1. 段落注释
2. 声明
3. 实现

## 第七部分：总线协议（L2-L3）

### 7.1 总线选型

| 场景 | 总线 | 信号 |
|------|------|------|
| 任务控制 | taskbus | sox, eox, pd |
| 单向数据 | vldbus | dat, vld |
| 流控 | hskbus | valid, ready, dat |
| FIFO 接口 | fifobus | wr_en, wr_dat, rd_en, rd_dat |
| 存储器访问 | bufbus | en, addr, dat |

### 7.2 taskbus 关键规则

【规则】sox_pd 在 sox 时刻可用

【规则】xwk_pd 在 en/vld/xwk 时刻可用，xwk 期间保持不变

【规则】相位：sox → xwk 拉高 → eox → xwk 拉低

【规则】**sox_pd 和 xwk_pd 必须解耦**

### 7.3 hskbus 关键规则

【规则】**valid 禁止撤销**：拉高后，握手完成前禁止自行拉低

【规则】**数据稳定**：valid 期间关联数据禁止翻转

【规则】**禁止反向依赖**：master 的 valid 不能依赖 slave 的 ready

## 第九部分：流水线设计方法（L1-L2）

### 9.1 三项评价指标

| 指标 | 定义 | 优化方向 |
|------|------|---------|
| **频率** | 最高工作频率 | 关键路径优化 |
| **吞吐率** | 单位时间处理数据量 | 气泡消除 |
| **延迟** | 单数据从入到出的时间 | 级数优化 |

### 9.2 启动三要素（源头控制原则）

```text
启动条件 = 前有数 && 后有空 && 状态合适
```

- **前有数**：读端不空（RC ≥ RA+RP+保护）
- **后有空**：写端不满（N-WC ≥ WA+WP+保护）
- **状态合适**：无冲突、无依赖、模式匹配

**FIFO 深度公式**：`N ≥ WA+WP+RA+RP+2F`
- WA/RA：写/读地址生成延迟
- WP/RP：写/读数据通路延迟
- F：缓冲余量

## 第十一部分：CDC 跨时钟域设计（L1-L3）

> 详见 [05.CDC 跨时钟域设计指南](../guide_ext/05-CDC跨时钟域设计指南.md)

### 11.1 CDC 信号分类与同步方案速查

| 信号类型 | 同步方案 | 关键约束 |
|---------|---------|---------|
| 单 bit 电平 | 2-FF / 3-FF 同步器 | FF 之间无组合逻辑 |
| 单 bit 脉冲 | 脉冲同步器（Toggle） | 脉冲间隔 ≥ 2×max(T_src, T_dst) |
| 多 bit 数据（慢→快） | 格雷码 + 2-FF | 每次仅翻转 1 bit |
| 多 bit 数据（快→慢） | 握手协议 / 异步 FIFO | 数据速率 ≤ 时钟速率/4 |
| 总线 | 异步 FIFO / 异步 Bridge | 深度 2 的幂次 |

### 11.2 CDC 关键规则

【规则】同步器第一级输出 → 目标域：设置 `set_false_path`

【规则】异步时钟对 → SDC 中声明 `set_clock_groups -asynchronous`

【规则】CDC 路径必须通过工具（SpyGlass/Questa CDC）静态检查

## 第十四部分：综合优化（L1-L2）

> 详见 [08.综合优化指南](../guide_ext/08-综合优化指南.md)

### 14.1 综合陷阱速查

| 陷阱 | 原因 | 修正 |
|------|------|------|
| 时序逻辑用了 `=` | 阻塞赋值在时序逻辑中破坏寄存器链 | 改用 `<=` |
| 组合逻辑用了 `<=` | 非阻塞导致仿真与综合不匹配 | 改用 `=` |
| 缺 `else` / `default` | 综合推断意外锁存器 | 补全分支 |
| 组合逻辑环路 | 振荡或不确定行为 | 寄存器切断 |

### 14.2 综合结果分析流程

```text
综合 → 关键路径报告 → 识别瓶颈 → 判断类型 → 决定策略
                                              ├── 组合逻辑过深 → 流水线化
                                              ├── 大扇出 → 复制寄存器
                                              ├── 约束不当 → 修正 SDC（如加多周期）
                                              └── 后端问题 → 交付后端处理
```

### A.2 设计原则速查

1. **简单原则**：一个信号只做一件事
2. **名副其实**：名称 = 含义，有效区间 >= 使用区间
3. **最小能量**：最少有能量信号把控进程
4. **源头控制**：只在流水线源头控制
5. **先空间后时间**：先定要素再定时序
6. **总线化**：模块接口尽量总线化
7. **解耦**：sox_pd 和 xwk_pd 必须解耦
8. **禁止反压**：禁止跨级反压
9. **不用状态机**：控制逻辑用任务分解 CBB 实现（三状态随机握手例外）
10. **信号含义完整**：属性 + 时刻 + 行为
11. **CDC 有同步器**：所有跨时钟域信号通过标准同步器
12. **SDC 全覆盖**：无未约束的时序路径
13. **功耗在设计**：从 RTL 编码阶段控制，非后端补救
14. **综合可追踪**：每次综合结果需反馈到 RTL 改进
